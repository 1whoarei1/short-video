# 连续形变与操作因果

这份参考配合 [video-motion](../.agents/skills/video-motion/SKILL.md) 与 [创作与验收参考](creative-method.md)，把柔和形变、主体承接和可信操作变成可实现、可检查的方法。[continuous-motion 示例](../examples/continuous-motion/README.md) 提供可运行代码；它是一种解法，不是所有视频的版式或时间表。

## 先确定谁在变化

用一句话说清这段的视觉主语和变化，例如“一条消息展开成资料，再收成完成标记”。观众能追踪的是同一个东西：轮廓、核心色、标识、位置轨迹或内容线索至少有合理的承接。一个场景可以有多个对象，但这次形变的语义主体应明确。

把连续主体看作同一几何状态，而不是提前摆好几张卡片、轮流改透明度。可用中心、宽高、圆角、旋转等描述；自由形状则用可对应的路径点或轮廓参数。DOM、SVG、Canvas 都可以，不要求固定元素 ID，也不要求只用一个 DOM 节点。

```js
// 概念接口，字段按作品需要选择。外壳与锚点读同一份状态。
const body = sampleBody(t); // { cx, cy, width, height, radius, angle }
const grip = localToWorld(body, { u: 0.5, v: 0 });
drawShell(body);
drawIdentity(body);
drawContents(body, t);
```

外壳、描边、阴影、裁切、内容布局和操作锚点都从这份状态派生。不要让 CSS 变宽、Canvas 裁切和光标路径各有一套独立估计。跨 HTML 镜头可共用同一场景采样函数，加各镜头的绝对时间偏移；在交界两侧验证视觉位置与速度，而非只核对节点名称。

识别线索可以是随主体移动的小印记、同一条边、某个切角或材质。不必永远保留所有装饰，也不要把相同主色当成唯一的身份依据。圆点变成线路节点、纸条折成纸盒、物件展开成局部剖面都可用同一思路，无需套成产品 UI。

## 外壳与内容各有节奏

先设计少量语义形态和承接路径，再决定哪一段舒展、哪一段干脆。尺寸、位移、圆角不必同步到达，也不必每一项都弹动；在不破坏主体感的情况下错峰，通常比整块统一缩放更有生命力。

- 旧内容可先淡出或随裁切收起，外壳接着扩展；新内容在空间足够时分组显露。可以有短重叠，但不能两套正文叠成不可读的噪声。
- 内容随新的可用区域重排，文字保持合理字号。直接把整张卡片拉伸，容易把字、图标和描边一起压扁；短促的形变效果也要检查实际可读性。
- 裁切与外壳共用当前轮廓。Canvas 用成对的 `save/clip/restore`，SVG 更新对应 `clipPath`，DOM 检查 `overflow` 和当前圆角；阴影通常画在内容裁切之外。防止旧内容漏出缩小中的壳。
- 外壳尺寸必须为有限正数。可在对数尺寸空间求弹性值后取 `exp`，再检查数值范围；也可采用不穿过零的有界插值。不要直接把会过冲的进度套到接近零的宽高。
- 圆角不为负，且不超过当前短边的一半；透明度限制在有效范围。必要的数值夹取是防护，不是修复明显撞到边界的动画，过度夹取会造成速度折点。

不要为追求“丝滑”让所有信息缓慢漂浮。用变化速度区分触发、展开、阅读、收束；停留和利落动作同样可以属于柔和的整体节奏。先在实际配音或无声阅读节奏中试验，再微调参数，不照抄样例秒数。

## 弹簧改目标时保留速度

普通 easing 适合一次完整的起落。弹性主体在尚未停下时再次收展，或光标拖动后释放，关键是继承当前状态。每次重新从静止启动的新弹簧，可能位置没跳，速度却突然归零，造成顿挫。

以一维临界阻尼弹簧为例，目标为 `g`，起始状态是 `x0`、`v0`，频率参数 `omega > 0`，经过 `s >= 0` 秒：

```js
const a = x0 - g;
const b = v0 + omega * a;
const e = Math.exp(-omega * s);
const x = g + (a + b * s) * e;
const v = (b - omega * (a + b * s)) * e;
```

这是可任选的采样法；欠阻尼、关键帧和其他曲线也能成立。若要有回弹，可选稳定的欠阻尼解，但不要把回弹等同于必须多次振荡。无论用哪种方法，在改目标时刻 `tr`，先从前一段精确采样 `x(tr)`、`v(tr)`，把它们作为下一段的 `x0`、`v0`，下一段以 `t - tr` 采样。这样位置和速度连续；改变目标通常允许加速度变化。固定事件表可预先递推出各段初始状态，不依赖视频曾经播放到哪一帧。

拖动阶段若主体被约束在光标下，释放初速度取约束轨迹的导数，包含移动中的父容器或镜头变换。给拖动曲线明确的端点切线，或用固定时间差在同一函数上求导；不能使用“上一渲染帧的位置差”，后者会随帧率和 seek 顺序变化。若释放轨迹设计为停稳，可有意令速度接近零；不要无意地丢掉仍在运动的惯性。

宽、高、中心、角度可分别采样，但各自的重定向都要传递状态。对数尺寸若使用速度，传递的是对数域速度；换回真实尺寸时 `widthVelocity = width * logWidthVelocity`。不要混淆单位，也不要通过每帧积分补救采样接口。

## 光标用来说明操作

只有操作本身值得观众看见时才加入光标。它可以服务点击、拖动、调整或选择，不必贯穿全片；非交互题材完全可以省去。使用时，把它写成有因果的动作，而不是飘过画面的装饰。

1. 到达：尖端沿有意的路径进入目标附近，减速停到真实锚点。
2. 悬停：给观众认出目标的机会；高亮、轮廓或轻微响应只在进入目标时发生。
3. 按下：在接触之后或同一时刻开始按压反馈，保持抓取点；触发响应不能早于操作。
4. 拖动：只有需要拖动时才有这一段，按下状态持续，主体或可拖部分随约束移动。
5. 释放：松开反馈先成立，随后保留释放速度进入回弹或落位；点击只需按下与释放，不强加拖动。

这是一组可选动作及其语义顺序，不是强制五拍模板。到达速度、悬停时长、按压幅度和反馈延迟取决于叙事与阅读需要。无操作含义的自动展开不应伪装成光标触发。

### 用同一坐标链计算接触

先从当前主体几何求局部锚点，经对象变换得到世界坐标，再经过镜头得到画面坐标。光标如果绘制在屏幕覆盖层，就使用最后这个坐标；若画在相同世界层，则两者一起经过镜头，不要重复变换。

```js
const worldGrip = bodyTransform(t).apply(localGrip(t));
const screenGrip = cameraTransform(t).apply(worldGrip);
// tipLocal 是光标图形内部真正尖端的位置，不是图形包围盒中心。
const cursorOrigin = subtract(screenGrip, cursorLinearTransform(t).apply(tipLocal));
```

最后一步的线性变换只包含光标自身旋转/缩放，不含平移。CSS `transform-origin`、SVG `viewBox`、Canvas 绘制起点都会改变实际尖端；先画调试点核对再去掉。拖动时保留按下那一刻的抓取偏移，避免目标突然跳到光标中心。

页面 CSS 缩放、设备像素比、画布内部坐标和摄像机缩放不能混用。可在固定设计坐标下计算场景，再统一映射到输出尺寸；测试不同画幅时重新设计布局，不能仅靠缩放掩盖接触误差。检查按下、拖动中和释放前后的“尖端到锚点距离”，同时实际看它是否像抓住了东西。

## 绝对时间与渲染桥接

建立纯采样入口 `render(t)` 或 `sample(t)`：在固定内容、随机种子和事件表下，任何时刻的几何、透明度、内容、按下状态及镜头都可直接重建。`requestAnimationFrame` 只负责预览时向这个入口提供时间；`Date.now()`、CSS 自行播放动画、累加 `dt` 的物理状态和只执行一次的事件回调不能成为离线画面的唯一来源。

- 每次采样重设本帧全部状态。倒序后不能残留上一次的文字、遮罩、Canvas transform 或按下标记；随机素材采用固定种子或预生成数据。
- 给每段明确的时间边界，事件时刻只属于一个确定状态；特殊处理首帧和终点，避免零时长除法。输出含 NaN/Infinity 时应报错定位，不能当作看不见的元素继续导出。
- 镜头切分用局部时间加固定 offset 获取同一逻辑时间。更改时长或 fps 后同步 `layout.json`、总帧数及相关时间轴，配音项目依真实音频重建。
- 使用现有 GSAP 时间轴，或把原生采样器接入真实 `window.__tl`。当前渲染器调用 `__tl.pause(t, false)` 并读取 `time()`，桥接还提供 `duration()`；调用 pause 时必须停止预览时钟并同步绘制指定时刻。仅暴露 `__seek` 没有完成接入，不覆盖已有真实时间轴。
- 已使用主题播放器时可复用 `theme-packs/shared/engine-bridge.js`，其前提是已加载 `player.js` 并存在对应 `render`。独立场景参考示例的真实适配；不要只复制同名全局变量而遗漏暂停、时长或当前时间。
- 图片、字体和异步素材真正就绪后再采样；适用时放入 `window.__assetsReady`。导出的实际帧中仍要检查缺图、替代字体和文字溢出。

只有作品明确要循环播放时，才设计首尾接缝：比较视觉状态、速度、光标状态、内容和镜头，并留意最后编码帧与下一轮首帧。普通短片可以自然收束和停留，不为了无缝循环倒放整个叙事。循环预览不是成片已经首尾连续的证据。

## 两条验收线分开记录

先解决最难的形变或抓取段，连续播放查看，再扩展完整作品；关键位置取样可以帮助诊断，但不能代替观看运动。

| 检查线 | 实际检查 |
| --- | --- |
| 内容与运动观感 | 观众能否追踪主体；触发和响应是否可信；柔和与利落是否服务语义；外壳形变是否有轮廓变化；文字是否来得及读；标识、材质与画面语言是否承接 |
| 确定性与几何 | 同一时间重复、倒序和乱序截图一致；重定向/释放两侧位置及速度连续；尺寸为正且有限；圆角和裁切有效；接触尖端和锚点吻合；无旧内容残留 |
| 编码后媒体 | 导出实际 MP4 并完整解码，核对画幅/fps/帧数/时长和实际音轨；播放关键运动、转场及结尾，检查编码代表帧；有音频时另外核对同步与听感 |

可围绕每个关键时刻 `tr` 采样 `tr - ε`、`tr`、`tr + ε`，再跨多个帧步检查速度。ε 与误差容限应结合单位和输出帧率；数值连续不等于视觉节奏正确。高速细节、光标尖端和细描边在浏览器与编码视频中都要看，不因浏览器截图正常而跳过 MP4。

验收报告区分“测过”“看过”和“听过”：seek 哈希只能支持确定性结论，媒体探测只能支持格式参数，代表帧不能证明连续动画顺滑。未能播放或未能听审时明确限制，不写成审美已通过。所有检查放在当前 manual/semi/auto 的制作与导出内，不增加人工 gate，也不把某次成功作品的蓝色、UI 外观、14 秒或固定节拍当成通用要求。
