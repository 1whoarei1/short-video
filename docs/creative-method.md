# 文稿、图形讲解与成片验收

这是 [旁白技能](../.agents/skills/video-narration/SKILL.md)、[视频工作流](../.agents/skills/video-workflow/SKILL.md) 与 [图片素材技能](../.agents/skills/video-image-assets/SKILL.md) 共用的取舍和验收参考。它服务用户当前主题、时长与审核模式，不提供固定文案或视频模板。

## 一件事怎样讲得值得看

先确定这次观众要记住什么、开头承诺什么，以及用户排除哪些旁支。围绕重点挑具体事实、动作、机制和例子；背景只留理解所需的部分。开头可以从现象、问题、细节或结论进入，正文要兑现它。重点讲清时就可以结束，不为凑三分钟补历史、清单或升华，也不把某次约53秒的成功变成标准时长。

用户明确要综合介绍或多个必讲要点时，保留授权范围并组织主线，不机械删成单点，也不改成自认为更稳妥或更实用的另一角度。来源链接先实际打开、确认有效并阅读正文。

适度危机感可以来自事实、日常场景和信息逐步揭示。不能编造危险、把风险说成必然，或把一种分类等级换算成个体患病概率。必要限定留下，额外的数字、建议和假想误解不自动成为新段落。少用纠正式“不是X而是Y”，有真实需要解释的区别时自然说清。

以下是不同请求的取舍方向，供判断，不能照搬句式：

| 用户这次要讲什么 | 有用的内容 | 应由新需求决定的旁支 |
| --- | --- | --- |
| 公司如何让配送异常更容易追踪 | 一件货物、一次异常、记录如何连起来、可核验结果 | 创始人履历、全部产品、市场规模、空泛使命 |
| 缓存为什么能省下重复工作 | 请求→已有结果→直接复用，以及适用条件 | 所有缓存算法、发展史、未请求的性能数字 |
| 加工肉的一类致癌分类与日常辨认 | 分类的必要含义、加工方式、具体食品例子 | 用户排除的18%/50g、安全量、替代食品与习惯建议 |

最后一例的准确边界：Group 1描述对人类致癌证据充分，不能据此说不同同组物质风险大小相等。这是核验约束；分类处自然解释证据充分即可，正文没有同组类比或风险数字比较时，不另追加澄清段。食品例子按实际腌制、发酵、烟熏等加工方式判断。[WHO原始问答](https://www.who.int/news-room/questions-and-answers/item/cancer-carcinogenicity-of-the-consumption-of-red-meat-and-processed-meat)可供查证；每次新制作仍重新核验需要使用的事实。

## 分镜交接与真实时序

纯口播只交口播。用户需要分镜或图文交接时可这样分开：

```text
【画面：一条请求进入，已有结果沿原路径返回。保留同一对象，接到下一镜头。】
这个结果已经算过，下一次请求就能直接复用。
```

画面提示与来源说明留在分镜稿或独立资料；引擎的 `narration.json` 中 `text` 只放已批准的口播，`|`仅用于已有字幕分段契约。画面文字不进入TTS。批准后制作不擅自扩写、替换词语；确需改文稿时用现有revise流程，并重建相关配音、字幕和时序。

先合成实际配音，再据音频长度和真实词边界安排字幕、关键视觉及场景长度。估时可用于构思，不能冒充实测。记录“哪个动作跟哪个词/段对应、依据与误差”；只有确实对应并验证的动作才称词级同步。无声模式仍按可读的字幕节奏制作，不为检查偷偷加配音。

## 图形怎样推进解释

逐句或逐段问：观众需要看见什么关系、变化、比较或因果？可让主体先出现，逐步变化或建图，再标原因、得到结论；也可按内容采用拆开、连接、聚拢、局部观察等办法。这个顺序是可选构思，不是每幕模板。

镜头内部需要有语义推进：关系逐步建立、状态改变、原因落到对应位置。可以留必要阅读时间；不要求每毫秒运动，也不靠闪光、漂浮和背景装饰冒充解释。跨镜头保留或变形核心主体，让观众跟得上。数字图形需要适当保留基期/比较对象，原因标注贴近对应变化，而不是把数据读成一屏文字。

先确定全片/系列的字体、核心palette、材质、标识及主体身份。构图和镜头自由变化；明暗段落可以有意切换，但保留这些连续线索。写实物件和扁平卡片不能未经协调就拼成两种设计语言，可通过光线、底色、描边、纹理与形状协调。不将任何一部食品片的暗色或底色固定为其他题材的默认。

原生生图按需实际生成、保存、解码和登记，再用于HTML。图片负责适合它的质感和物件；关系、数据与准确文字可以由SVG/Canvas/HTML表达。素材包是可拆、可改、可组合的材料。实际接口和示例见 [视觉材料工作法](visual-remix-guide.md)；只定义独立`__seek`不能冒充已接通渲染契约。

## 声音与成片检查

读取本项目渠道、音色、语速、BGM及明确选用的组合。Azure云帆+40%只是可选组合，默认仍依项目状态；不给所有视频固定音色、语速、增益或53秒长度。统一试听的本地变速与最终TTS节奏/停顿有差别，按 [音频预设说明](audio-presets.md) 诚实说明。

人声期间音乐隐约可闻，停顿时适度恢复，ducking由实际配音控制。以本项目与用户反馈调整，不盲抄上片dB；核对独立音乐源、最终混音、峰值、同步及结束点。只改BGM或音量时保留原配音、字幕和画面缓存，重建混音与绑定记录；不反复叠加旧混音。

| 检查层 | 实际做什么、记录什么 |
| --- | --- |
| 文稿 | 一件事是否突出、开头是否兑现、是否偷偷加旁支、事实和必要限定是否准确；按听的顺序通读 |
| 动画与审美 | 连续播放关键解释段与转场，查看编码后的代表帧；检查镜头内语义推进、关系讲解、活泼感、字幕可读和风格连续性 |
| 技术媒体 | 全片严格解码、关键位置及正反seek、实际分辨率/fps/帧数/时长、音轨与字幕同步、峰值与削波、输入/续渲/混音哈希 |
| 听审 | 实际听配音和音乐的关系、停顿与尾部；仅做波形/RMS/LUFS或模拟夹具时明确范围，不声称听过 |

自动化测试绿不代表美感、内容或听感过关；逐项说明实际看过、听过、测过什么，未做的留为限制。[manual/semi/auto](workflow-modes.md)继续生效：全自动可在制作/导出内执行这些检查，不增加静态预览或其他人工gate。复用已有且已核验的媒体时，检查改动涉及的层，不为低影响文档或增益调整重做TTS或画面。
