# 第五轮：空间讲解资源与新机可用性

## 创作能力
新增 signal-journey「信号旅程 · 空间讲解」资源包：12 秒、四段演进，让一个消息沿路径进入、分路、汇合，再到达下一站。用层叠平面、镜头深度、沿线物件与局部强调解释抽象关系。提供空间飞行与平面路线两种可运行变体、四个原创 SVG 和可改写几何参数，复用共享运动与预览代码。

参考方法和原始代码/资产的许可分别保留。图形仅表达抽象关系，不作为真实网络结构证据。现有资源总量为 13 包 + 23 个风格动态参考，并保留原创方向。

## 工作台与首次使用
- 320px 页面横溢定位到阶段按钮最小宽度，已修复；长项目名、主题名、对话框操作行可以正确换行。没有通过裁掉页面掩盖问题
- 320/360/390/768/1440px 下检查三分组需求、主题与音色、图片/视频原生预览、进度拖动和批注；查看不保存草稿、不启动任务，也不改用户选定音色或语速
- 环境检查明确区分 Python-only UI、渲染依赖、Pillow 图片登记、可选声音和当前会话原生 AI 工具；增加 ffprobe 检查与 --json
- Windows npm.cmd 通过官方 npm CLI JavaScript 入口调用，不启用 shell；macOS 浏览器路径检查完善
- 新机器指南涵盖重新克隆、Codex 新会话、工作台、个人项目迁移和凭据由用户本人在本机配置

## 核验与修复
- 198 项 Python 测试、18 组既有及小屏浏览器/渲染测试通过，另有时间轴错误输入测试通过
- 全部 13 包动态预览检查通过；信号包两个变体均做乱序取帧、冻结、引擎桥接、减少动态和手机检查
- 原有纸艺包在极端跳帧后出现 198 像素的 Chromium 图层重绘差异。为运动鸟形 SVG 独立合成图层后连续五次通过，未放宽像素阈值
- 信号包经实际 copy 命令进入新项目，再用现有引擎输出 12 秒、288 帧、1280×720、24fps、H.264 无声视频，完整解码通过
- 发现手写错误结构的 layout 会被当作一帧成功导出。渲染器现对缺失、非数值、非正场景时长及无效声明帧数直接报错；有效时长的既有渲染通过
- Linux 真机检查通过；禁用 Python site-packages 时仍可启动 UI 并返回健康检查，Pillow 被如实标为缺失。Windows/macOS 仅路径与调用模拟测试，尚未原生验收
