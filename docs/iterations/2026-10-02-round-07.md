# 第七轮：自由重组样片与干净项目验收

## 真正用材料做一支新片
新增 `examples/mountain-letter/`《山间来信》，28 秒无声概念短片。一封信从雾中山谷出发，展开为不对称的触感记忆页，再收拢落到窗边。

实际拆用了山脊、松枝、两张版画、折纸鸟及纸张颗粒，重新编写信封主体、展开运动、路径、构图与中文短句。全过程由一个持续主体连接，资源包原来的预览没有直接拼成最终视频。来源和逐文件哈希保留在示例里。

实际输出 1280×720、24fps、672 帧、28.000 秒、H.264、3,339,946 字节，无音频流。完整解码通过，MP4 解码后的 3/14/27 秒帧已查看；14 个代表时刻反序重访像素哈希一致。

## 使用与恢复
新增自由材料改编指南，从当前一句话的视觉作用出发，检索少量材料、做关键运动与代表帧，再自由扩展。包括资源复制、异步图片准备、时间轴、来源与审美检查；沿用五阶段与用户选择的声音。

在独立干净目录实际解压上一轮的完整源码：Python-only UI 启动、空白新项目与需求保存、15 包目录、23 份字体和 5 份试听均通过。安装锁定依赖后，登记已有真实生图素材并导出一段 12 秒片。以基础提交和增量 bundle 恢复到准确目标，487 个文件逐字节一致。详情与范围见 `docs/clean-checkout-verification.md`。

这并非新开了一个 Codex 对话的模型行为测试；也没有伪造人工审批。Linux 实测、Windows/macOS 原生未实测，以及精确生图型号与 Luna 质量对照未验证，均明确保留。

## 一个实际接入问题
检查渲染成片时发现：本项目输出可能是 H.264 的 full-range 8-bit 4:2:0（ffprobe 标为 yuvj420p），旧的个人动态主题校验会拒绝它。实际 Chromium 播放、暂停和完成拖动后，现仅为 MP4/H.264 放行这一对应像素格式；WebM、其他编码和大小/时长限制保持严格。

新增真实 full-range 媒体的上传、保存、导出/导入、播放与拖动回归，并验证 10-bit/4:4:4 仍被拒绝。原有 WebM 流程继续通过。

本轮核验：206 项 Python 测试、22 组浏览器/渲染检查、15 包预览检查通过；像素确定性和真实导出分别核验。
