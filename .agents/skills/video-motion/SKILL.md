# 连续运动与因果交互

先读本次需求、已批准文稿与 [创作与验收参考](../../../docs/creative-method.md)，再按需要读 [连续运动实践](../../../docs/continuous-motion.md)。可运行、可拆用的实现见 [continuous-motion 示例](../../../examples/continuous-motion/README.md)。

- 找到这一段持续被观察的主语，确定它如何变化以及观众凭什么认出它。用共享几何状态驱动外壳、内容、标识、裁切与交互锚点；有语义联系的形态尽量连续演化，避免靠两套静态页面淡入淡出冒充形变。
- 柔和感来自轮廓、位移、速度与内容交接的配合。改目标、拖动释放时继承当刻位置和速度；外壳变化期间可错峰撤出旧内容、显露新内容，保留阅读空间。尺寸和裁切始终有效。
- 只有需要演示操作因果时才使用光标。到达、悬停、按下、拖动、释放要与对象响应一致；接触点由对象真实几何和同一坐标变换计算，校准光标尖端，不能只画一条看似靠近的轨迹。
- 每一帧只由绝对时间和固定输入求得。重播、倒序和乱序 seek 得到同一画面；原生 JS 接入实际 `window.__tl`，独立 `__seek` 不足以导出。
- 实际播放并检查导出的 MP4，再独立核验 seek、边界和媒体参数。技术通过不代表运动好看，静态代表帧也不能证明动画连续。只有明确制作循环时才要求首尾接缝；普通视频保留合适的结尾停留。

复用方法而非复制成片：颜色、材质、构图、主体、节奏、时长和是否出现光标都由当前内容与用户方向决定。沿用现有 manual/semi/auto 模式，不增加审核阶段，不修改已批准口播或声音选择。
